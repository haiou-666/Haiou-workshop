## 01 · 项目介绍

海鸥工坊是面向 **Codex、Claude Code 与 DeepSeek Harness** 的本地管理工作台。它将原本分散的配置安装、环境诊断、技能接入、REA 集成、备份与卸载恢复整理到统一入口，减少重复配置，让操作过程更清楚、出错位置更容易定位。

项目采用“**先选客户端版本，再选操作系统**”的组织方式。三个版本分别管理对应配置，避免把一个客户端的配置直接当作另一个客户端的配置使用；共享配置则尽量只处理本工具负责的条目。

### 适合哪些场景

- 需要同时使用多种 AI 编程工具，希望集中管理配置与启动入口。
- 不希望一次性安装大量体积较大的工具，希望按实际需要扩展环境。
- 希望看清安装阶段、执行日志与失败原因，而不是只看到一个等待窗口。
- 需要在配置调整前后进行校验、备份与恢复，降低误操作风险。
- 在获得授权的开发、学习、测试或分析环境中使用技能与扩展工具。

### 它不是什么

- 不是大模型本身，也不是账号、订阅、API 服务或调用额度的提供方。
- 不是“保证解除所有限制”“自动获得系统权限”的工具。
- 不是所有外部工具的全集安装器；大型工具采用独立、按需安装方式。
- 不是数据恢复软件；配置卸载不等于清除全部客户端数据或历史对话。
- 不是完整开源工程仓库；本仓库的文档和许可文件不代表已公开完整源码。

## 04 · 下载与首次使用

### 第一步：选择真正的程序包

前往 [版本下载页面](https://github.com/haiou-666/Haiou-workshop/releases)，阅读该版本说明后选择维护者实际提供的附件。

- 普通 Windows 用户优先选择 Windows 桌面程序包。
- 只需要某个客户端入口时，选择对应版本和操作系统的启动包。
- 如果尚无 Release 或没有程序附件，说明该页面暂未提供对应可下载程序，不要将文档包当成软件包。
- 自动生成的 `Source code` 归档只包含当前展示仓库的文件，不能替代完整程序。
- 既有附件名可能仍使用 `Seagull-` 前缀；项目展示名称统一为 **海鸥工坊 · Haiou Workshop**。

### 第二步：解压与启动

1. 将下载的 ZIP 完整解压到自己可读写的目录，不要直接在压缩包中运行。
2. 运行 `海鸥工坊.exe`。先观看入场动画，再阅读公告与使用须知，同意后进入主界面。
3. 如果系统发出安全提示，先检查下载来源和文件信息，不要为了启动而关闭安全软件或全局降低系统保护。
4. 初次使用时先确认主界面可正常显示，再进行配置操作。

### 第三步：选版本、查环境

1. 选择 **Codex / Claude / DeepSeek** 中实际要使用的版本。
2. 选择本机操作系统，查看界面显示的目标目录。
3. 检查客户端、运行环境、网络与目录权限是否满足要求。需要时使用环境检查或诊断入口。
4. 如果已有个人配置或正在使用的项目，先自行备份，不要把“工具会备份”当作唯一保障。

### 第四步：安装配置

1. 点击“安装配置”，确认选择的是正确版本和目录。
2. 观察操作日志、当前阶段和耗时；某些依赖检查或网络步骤可能需要等待。
3. 不要在同一次操作尚未结束时反复点击安装、卸载或同时手工修改目标配置。
4. 以日志中的明确完成结果为准。出现失败、非零退出码或未完成提示时，应先排查对应错误。
5. 普通配置安装与大型工具安装分开进行；不需要的大型工具可以不装。

### 第五步：校验并实际验证

1. 点击“校验配置”，检查是否存在缺失、变化或冲突提示。
2. 启动对应客户端，完成自己的账号、API 或模型设置。
3. 配置或角色指令发生变化后，新建会话进行验证；必要时退出并重新启动客户端。
4. 先用不涉及敏感数据的简单任务测试，再逐项确认自己需要的技能或工具。

> **请区分三个结果：**“文件已安装”“配置校验通过”“真实任务能完成”不是同一件事。模型可以对自己的状态作出不准确描述，因此还应结合实际文件、日志和任务结果判断。

### macOS / Linux 使用提醒

下载对应版本的系统脚本包，完整解压后先阅读包内说明，再按说明准备依赖和执行入口。不要从不明来源复制大段高权限命令，也不要因为本地存在脚本就假定已经完成平台兼容验证。

## 05 · 配置、技能与扩展工具

### 配置安装不等于安装所有工具

“安装配置”主要处理相应客户端的受管配置、技能接入和 REA 集成。大型逆向分析工具不再随普通配置安装自动成套下载，应根据实际需要在工具中心独立选择。

这种方式可以减少不必要的下载与磁盘占用，但不意味着配置安装完全不需要联网、依赖或额外空间。具体需求以操作日志和所选组件为准。

### 技能与 REA 如何理解

- 技能是组织工作流程、提示说明或工具使用方式的资源，不等同于已经安装完成的外部程序。
- REA 接入随对应版本的配置流程管理，不需要将其理解为另一套独立主界面。
- 某个功能所需的程序、运行时、权限或网络条件缺失时，即使技能文件存在，该功能仍可能无法工作。
- 本展示仓库没有附带数百个技能正文或原始归档；请勿把“支持技能接入”理解成“下载本仓库即可得到全部资源”。

### 角色与指令效果的边界

海鸥工坊以“海鸥”作为项目角色与品牌表达，但模型的最终回复还会受到既有会话、客户端规则、项目级指令和模型本身影响。安装配置不能保证每次回复都呈现相同称呼、人格或语气。

如果出现旧称呼或其他人格残留，请先确认使用的客户端与配置目录，再新建会话；不要仅凭一句自我介绍就判断配置已全部失效，也不要因此删除全部用户数据。

## 06 · 更新、备份与卸载

### 更新前

- 先阅读更新说明，区分“文档更新”和“程序更新”。替换 README 不会修复已经运行的旧程序。
- 备份重要配置，并确认当前安装或卸载操作已经结束。
- 更换程序前退出旧窗口，更新后确认启动的是新文件，避免仍在使用旧路径或旧快捷方式。
- 不要使用不明来源的安装包覆盖正在工作的配置环境。

### 卸载处理的范围

| 情况 | 处理原则 |
|---|---|
| 受管文件已经被手动删除 | 正常跳过，不因“文件不存在”重复报错 |
| 本工具创建的独立受管文件 | 依据安装记录处理；必要时先保存卸载前快照再移除 |
| 安装前已有的文件 | 在可核验的条件下恢复原内容，不盲目覆盖后续个人修改 |
| 多个组件共用的配置文件 | 只处理能够确认属于本工具的条目，尽量保留其他内容 |
| 无法安全识别归属或存在冲突 | 保留现场并报告问题，不强行清空整个文件 |

卸载受管配置通常不等于卸载客户端，也不等于清除账号、历史会话、个人项目、共享运行环境、大型工具或已有备份。

**发现卸载失败时，请保留完整错误信息并停止重复尝试。不要手动删除整个用户配置目录来“强制修复”。** 备份本身也可能包含敏感信息，不应上传到公开仓库或交流群。

## 07 · 常见问题与排查

| 现象 | 先检查什么 | 建议处理 |
|---|---|---|
| 安装进度较久没有变化 | 当前阶段、最后一条日志、网络与依赖状态 | 不连续重复点击；记录停留阶段和耗时后排查 |
| 配置校验正常，但模型不可用 | 客户端登录、API 配置、模型权限及网络 | 将配置问题与服务连接问题分开检查 |
| 删除配置后仍出现旧人格 | 是否仍在旧会话，是否读取其他项目规则或另一份配置 | 确认路径，重启对应客户端并新建会话 |
| 安装后某个技能不能用 | 该技能所需程序或运行时是否存在 | 单独补齐必要依赖，而不是安装全部工具 |
| 卸载提示共享配置冲突 | 错误涉及哪个文件，是否存在人工修改或其他组件条目 | 保留文件与日志，不绕过保护机制 |
| 已更新程序但界面没有变化 | 启动文件路径、旧进程、快捷方式目标 | 退出旧程序后从新位置重新打开 |
| macOS/Linux 启动失败 | 是否选对系统包、依赖是否满足、脚本说明 | 提供平台与日志；这些平台尚未完成原生实机验收 |
| 安全软件拦截文件 | 下载来源、文件信息、发布者提供的核验资料 | 先核实来源，不建议全局关闭防护 |
